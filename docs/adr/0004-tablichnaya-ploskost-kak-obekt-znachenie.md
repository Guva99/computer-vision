# ADR 0004. Калибровка плоскости стола — объект-значение, а не запись в конфиг

Дата: 2026-10-27. Статус: принято. Шаг плана: S1.3.

## Контекст

Загрузчик `table_plane.json` писал значения прямо в конфиг:

```python
self.cfg.collision_obj_plane_height_min_m = float(data["gate_min_m"])
```

Последствия:

- **действующий порог не совпадал с заявленным**: в калибровке 0.04 м, в
  AppConfig 0.025 м. Работал первый, а в мету прогона и в любой дамп
  параметров попадал второй;
- конфиг — общий объект: его видят раннер, рекордер, логи. Изменение в одном
  сервисе меняло картину для всех, причём незаметно;
- требование методики «параметры зафиксированы до прогонов» (EXPERIMENTS.md)
  формально нарушалось: часть параметров определялась файлом калибровки в
  момент старта.

Порог высоты — не второстепенная настройка: предмет ниже него не выделяется
вообще. Это заявляемая граница применимости метода.

## Решение

Калибровка читается в неизменяемый объект-значение `TablePlane`
(`vision/table_plane.py`): плоскость, `gate_min_m`, `gate_max_m`, `roi_px` и
источник. Применение — отдельной функцией `apply_to_config()`, которая возвращает
**копию** конфига (`dataclasses.replace`) с действующими значениями. Внешний
объект не меняется. `CollisionService.effective_gates` отдаёт действующие пороги
для меты прогона и отчётов.

## Что отвергнуто

- **Убрать приоритет калибровки над конфигом** (брать пороги только из
  AppConfig). Это изменило бы поведение: детекция пошла бы с порогом 0.025 вместо
  0.04, то есть иначе, чем в уже собранных 41 записи.
- **Передавать пороги отдельными аргументами в детектор.** `detect_scene_objects_2d`
  и так принимает 9 аргументов; рост числа аргументов ловит архитектурный тест,
  и он прав — функция подлежит разбору на шаге S3.2.

## Последствия

- действующие пороги печатаются при старте и доступны программно — их можно
  писать в мету прогона (S4.1) и в раздел «Экспериментальная установка»;
- расхождение «заявлено 0.025 / работает 0.04» перестало быть скрытым;
- после пересъёмки плоскости меняется чувствительность детекции — это видно в
  логе прогона, а не только в файле калибровки.
