# Правка KRL: два CASE, которые нужны для техпроцесса

Что и зачем добавить в программу-диспетчер на контроллере, как это проверить, и
почему именно так. Для переноса на пульт.

## Зачем вообще править

Сейчас диспетчер умеет двигать робота только **декартовыми** целями
(`CASE 4` — LIN по массиву, `CASE 5` — PTP по массиву). Для сборки башни это
два риска:

1. **конфигурацию суставов выбирает обратная кинематика контроллера.** При
   A4 ≈ 168.7° она уже уходила за границу оборота ±180° → останов KSS01211
   (записано в шапке `robot/drivers/kuka_driver.py`);
2. **точность**: декартовы цели у нас считались через DH-модель, а она врёт —
   заявленная длина хвата 137 мм против ~88 мм по подбору. Для захвата кубика
   это промах.

Переменная `COM_E6AXIS` в программе **объявлена, но ни один CASE её не
использует** — поэтому осевое движение в коде написано (`KukaDriver.ptp_axis`),
но отключено.

## CASE 11 — PTP в осях

Движение в заданные углы. Пересчитывать нечего, конфигурация суставов не
меняется, граница A4 не грозит.

```krl
CASE 11   ; PTP в осевых координатах: цель лежит в COM_E6AXIS
   PTP COM_E6AXIS
   COM_CASEVAR = 0
```

## CASE 12 — вертикальное смещение на заданное число миллиметров

Подход к кубику и отход после захвата: прямая вертикаль на расстояние, которое
считает Python. Знак задаёт направление (минус — вниз).

```krl
   ; в списке данных программы (DAT), рядом с остальными COM_*:
DECL FRAME COM_DZ

   ; в SWITCH:
CASE 12   ; LIN по вертикали BASE на COM_VALUE1 мм
   COM_DZ = {X 0, Y 0, Z 0, A 0, B 0, C 0}
   COM_DZ.Z = COM_VALUE1
   LIN_REL COM_DZ
   COM_CASEVAR = 0
```

Почему смещение, а не отдельная поза на каждый уровень: высота кубика известна,
поэтому вместо 8 заученных поз (подход + захват на каждый из четырёх уровней)
нужна **одна** поза над башней, а разницу уровней Python считает арифметикой —
`dz = высота_башни − уровень × ребро_кубика`. Меньше учить, меньше ошибаться.

> Проверить по месту: синтаксис агрегата и доступность `LIN_REL` зависят от
> версии KSS и от того, как написана существующая программа. Если `LIN_REL`
> относительно BASE не подходит (хват стоит не вертикально), используется
> вариант относительно инструмента: `LIN_REL COM_DZ #TOOL`.
>
> Главное требование к обоим CASE: **в конце обнулить `COM_CASEVAR`** — драйвер
> ждёт именно этого как признака «движение завершено»
> (`KukaDriver.ptp_axis`, ожидание в цикле чтения).
>
> `COM_VALUE1` переиспользуется (сейчас им задаётся `$OV_PRO` в `CASE 3`) —
> это безопасно, потому что команды идут последовательно, по одной. Если
> хочется чистоты, можно объявить отдельную `DECL REAL COM_DZ_MM`.

## Как проверять — поэтапно, не сразу движением

Инструмент для этого уже написан: `tools/test_axis_motion.py`.

```bash
python tools/test_axis_motion.py --probe                 # только чтение: углы, режим, COM_CASEVAR
python tools/test_axis_motion.py --null --casevar 11     # цель = текущие углы: робот не двигается,
                                                         # но видно, принял ли KRL команду
python tools/test_axis_motion.py --move 5 --casevar 11 --yes   # реальное движение A1 на 5°, режим T1
```

Этап `--null` — главный: он отвечает на вопрос «обработчик есть и он обнуляет
`COM_CASEVAR`», не двигая робота вообще.

Для `CASE 12` первая проверка — смещение на **5 мм вверх** (`COM_VALUE1 = 5`),
в T1, с рукой в свободном пространстве.

## Что это даёт процессу

Полный цикл «взять кубик с башни-источника и поставить в целевую» сводится к
последовательности из двух команд движения и двух команд хвата:

```
PTP(над источником)                  CASE 11
LIN_REL(вниз на dz_взять)            CASE 12,  COM_VALUE1 = -dz
закрыть хват                         CASE 7
LIN_REL(вверх на dz_взять)           CASE 12,  COM_VALUE1 = +dz
PTP(над целью)                       CASE 11
LIN_REL(вниз на dz_поставить)        CASE 12
открыть хват                         CASE 7
LIN_REL(вверх)                       CASE 12
```

Заучить на пульте нужно всего несколько поз: `home`, `transport`,
`над_источником`, `над_целью` (и по одной на каждую дополнительную целевую
позицию, если башен будет несколько). Всё остальное — арифметика по высоте
кубика.

## Что нужно замерить при наладке

| Величина | Зачем |
|---|---|
| ребро кубика, мм | считать `dz` по уровням |
| высота хвата над кубиком в позе подхода, мм | начальное `dz` |
| комбинация OUT5/OUT6: что закрывает, что открывает | `CASE 7` |
| время до фактического схвата, мс | пауза после `CASE 7` перед подъёмом |
| держит ли хват кубик без питания | поведение при аварийном останове |
| вертикален ли хват в заученных позах | выбор `LIN_REL` в BASE или `#TOOL` |
