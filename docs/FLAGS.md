# Инвентаризация переключателей AppConfig (S1.6)

55 булевых флагов — это 3.6·10¹⁶ формально возможных конфигураций, из которых
измерена ровно одна: та, в которой сняты 41 запись Э2/Э3. Каждый флаг,
выключенный по умолчанию, — это ветвь кода, которую не покрывает ни регрессия,
ни прогоны на стенде.

Цель инвентаризации — не «удалить всё лишнее», а знать про каждый флаг, в каком
он состоянии и чем покрыт. Удалять можно только то, что не описано в статье и не
нужно для серий; остальное остаётся, но осознанно.

Пересобрать список:

```bash
python tools/arch_metrics.py            # число флагов (храповик следит, чтобы не росло)
```

## Правило на будущее (бюджет сложности)

1. **новый флаг добавляется только вместе с тестом или записью в golden-набор,
   которая проходит по его ветви.** Иначе не добавляется;
2. выключенная ветвь либо покрывается регрессией, либо удаляется;
3. флаг-«тумблер алгоритма» (не визуализация и не сбор данных) после Фазы 3
   заменяется составом списка шагов конвейера — там ветвь видна в коде сборки,
   а не спрятана внутри функции.

## Группы

| Группа | Сколько | Статус |
|---|---|---|
| Режимы алгоритма (детекция, маски, коллизии) | 33 | рабочая конфигурация измерена; 4 ветви выключены |
| Визуализация (`show_*`, `perf_*`) | 10 | на решения не влияют; проверено совпадением playback с живыми прогонами |
| Сбор данных (`enable_*`, `recording_*`) | 8 | выключены по умолчанию, включает мастер серий; накладные расходы измерены |
| Настройка глубины камеры (`depth_*`) | 4 | используются только в `realsense_io.py` при старте потока |

## Выключенные по умолчанию ветви — что с ними делать

| Флаг | Что за ветвь | Решение |
|---|---|---|
| `collision_dbscan_adaptive_eps` | адаптивный ε для DBSCAN по k-distance | **НЕ удалять без решения автора:** описан в статье (ARTICLE_CONTEXT.md §3, формулы 5–6). Либо включить и измерить, либо убрать формулы из текста |
| `collision_use_2d_detection=False` (запасная ветвь) | детекция объектов через voxel → depth-percentile → DBSCAN в 3D, ~110 строк в `collision.py` | **НЕ удалять без решения автора:** это «запасной режим» из README и формулы 5–9 статьи. Кандидат на то, чтобы один раз прогнать на записях и отчитаться как об альтернативе |
| `collision_workspace_filter` | отбрасывание объектов вне рабочей зоны по координатам в базе робота | зависит от `T_cr` (RMS 21 px), поэтому и выключен. Оставить до перекалибровки; в статье упомянуть как доступный, но неиспользованный фильтр |
| `wrist_use_static_roi` | ROI запястья фиксированным прямоугольником вместо FK | кандидат на удаление: FK-вариант работает, статический нигде не описан |
| `detect_gripper_from_manipulator_mask` | альтернативный путь получения контура хвата | кандидат на удаление после Фазы 3 (детекция хвата всё равно переезжает за порт) |
| `depth_filters_enabled` | постобработка глубины на стороне RealSense | **оставить выключенным:** все 41 запись сняты с СЫРОЙ глубиной. Включение сделает новые данные несравнимыми со старыми |
| `show_*` (4 флага), `recording_compress`, `recording_joints_only` | визуализация и варианты записи | оставить: нужны для рисунков статьи и режимов съёмки |

## Что сделано в S1.6

Удалений не выполнено сознательно: две ветви из списка описаны в статье
формулами, и решение об их судьбе — за автором (включить и измерить либо убрать
из текста). Остальное помечено как кандидаты и будет снято после Фазы 3, когда
соответствующие куски уедут за порты и их удаление станет локальным.

Что уже закрыто вместо удаления:

- **127 инлайн-дефолтов снесены** (S1.1) — именно они делали флаги опасными:
  при частичном конфиге ветвь выбиралась не той, что в AppConfig;
- **храповик следит за числом флагов** (`tests/test_architecture.py`): вырастет —
  тест упадёт;
- **`tools/regress.py --compare флаг=значение`** позволяет прогнать любую ветвь
  по golden-набору и увидеть её вклад одной командой. Пример измерения памяти
  объектов:

```
python tools/regress.py --fast --compare collision_object_permanence=False
  OK  S01_baseline_empty   183 кадров  SAFE=183
  ОТЛИЧАЕТСЯ S04_cube_on_path: 29 кадров из 177
      golden : DANGER=12 SAFE=148 WARN=17   первый DANGER: кадр 71
      прогон : DANGER=0  SAFE=169 WARN=8    первый DANGER: нет
```

То есть на S04 без слоя памяти объект не доходит до решения вообще — ни одного
кадра DANGER. Это первая количественная оценка вклада `object permanence`
(в STAND_NOTES он числился неизмеримым из-за дефекта логирования `objects.csv`).
Проверить на остальных записях и на дополнительных повторах — отдельная задача
этапа Э4.
