# Программа контроллера KUKA (KRL)

Здесь лежит копия программы-диспетчера, которая крутится на контроллере и
исполняет команды, приходящие от Python через KUKAVARPROXY.

| Файл | Что это |
|---|---|
| `dist.original.src` | ровно то, что было на контроллере до правки (2026-11) |
| `dist2.src` | то же плюс `CASE 11` и `CASE 12` |
| `dist3.src` | то же плюс `CASE 20` и `CASE 21` — работа с магазином |
| `kkkk/` | рабочие программы стенда, из которых взяты координаты |

## Зачем копия в репозитории

Пока программа живёт только на пульте, расхождение между ней и кодом Python
ловится на стенде, а это дорого. У проекта такой случай уже был — в шапке
`robot/drivers/kuka_driver.py` записано: номера CASE в драйвере разошлись с
программой, движение по массиву шло как `LIN`, хотя метод назывался
`ptp_continuous`, а команда хвата слала номер 5 — это PTP, то есть движение.

Копия в git делает такие расхождения видимыми в diff, а для статьи даёт
воспроизводимость: по коммиту понятно, какая именно программа крутилась на
контроллере во время кампании.

**Правило:** правишь на пульте — обновляй копию здесь тем же коммитом.

## Что добавлено

```krl
  CASE 11
    PTP COM_E6AXIS
    COM_CASEVAR = 0
  CASE 12
    LIN_REL COM_FRAME #BASE
    COM_CASEVAR = 0
```

Больше ничего не изменено: ни одной существующей строки, включая отступы и
пробелы в конце строк. Проверяется `diff dist.original.src dist2.src` — видны только вставка шести
строк перед `ENDSWITCH` и переименование `DEF`.

**`CASE 11` — движение в осях.** Цель пишется в `COM_E6AXIS`. Пересчитывать
нечего, поэтому уходит проблема, из-за которой робот прокручивал A4 и вставал
по KSS01211: декартов PTP отдаёт выбор конфигурации суставов обратной
кинематике контроллера, и при A4 ≈ 168.7° она уходила за ±180°.

**`CASE 12` — относительное линейное смещение.** Вектор пишется в уже
существующую `COM_FRAME` (новых переменных не заводим — значит `$CONFIG.DAT`
трогать не нужно). Нужен для подхода и отхода: вынуть кубик из слота, опустить
на стопку, подняться.

`#BASE` означает, что смещение задаётся в системе BASE. Управление идёт с
`BASE = 0`, то есть смещение по Z — это вертикаль в мире. Если KSS не примет
суффикс, его можно убрать — поведение по умолчанию то же.

## Требование к Python при вызове `CASE 12`

`COM_FRAME` — полный кадр, у него есть и углы. Драйвер пишет все шесть
компонент (`KukaDriver.send_frame`), поэтому для чистого переноса **A, B, C
обязаны быть нулями** — иначе вместе со смещением произойдёт поворот.

## Имя программы

Файл назван `dist2.src`, чтобы не затирать рабочую программу. **Имя подпрограммы
внутри файла обязано совпадать с именем файла**, поэтому в нём стоит
`DEF dist2( )`, а не `DEF dist( )` — иначе контроллер файл не примет.

Старая `dist` остаётся на пульте нетронутой: если с новой что-то не так,
возврат — это просто выбор прежней программы, без восстановления из бэкапа.

## Перед заливкой

1. **Сохрани оригинал** на USB или оставь на пульте под другим именем.
2. **Проверь, что `COM_E6AXIS` объявлена** в `$CONFIG.DAT` и имеет тип `E6AXIS`.
   Если переменной нет, `CASE 11` не скомпилируется. Проверка без движения:
   прочитать её скриптом `tools/probe_krl_vars.py` — если значение читается,
   объявление есть.
3. Номера 11 и 12 свободны: в оригинале есть 1, 2, 3, 4, 5, 7, 8, 9, 10.
   `CASE 6` отсутствует вовсе.

## Проверка после заливки — по возрастанию риска

```bash
python tools/test_axis_motion.py --probe                # только чтение
python tools/test_axis_motion.py --null --casevar 11    # цель = текущие углы, робот стоит
python tools/test_axis_motion.py --move 5 --casevar 11 --yes   # A1 на 5°, режим T1
```

Этап `--null` — главный: он отвечает «обработчик есть и `COM_CASEVAR`
обнуляется», ничего не двигая.

Для `CASE 12` первая проба — смещение **+5 мм вверх** (`COM_FRAME = {X 0, Y 0,
Z 5, A 0, B 0, C 0}`), в T1, рука в свободном пространстве.

## Чего в программе трогать НЕ надо

- **Пустой цикл `LOOP ... ENDLOOP` без паузы.** Он нагружает интерпретатор, и
  рука тянется добавить `WAIT SEC`. Делать этого не нужно по двум причинам.
  Во-первых, скорость этого цикла определяет, как быстро контроллер подхватит
  команду останова, а время реакции — измеряемая величина статьи. Во-вторых,
  ПРОВЕРЕНО ЗАМЕРОМ (2026-11-03): цикл не мешает чтению переменных. При
  работающей программе и неподвижном роботе чтение `$AXIS_ACT` занимает
  медиану 4 мс — столько же, сколько при остановленной программе. Дорожает оно
  во время ДВИЖЕНИЯ робота (70–90 мс), и лечится это фоновым потоком чтения на
  стороне зрения, а не паузой в KRL.
- **`$ADVANCE = 0`.** Опережающий просмотр выключен, поэтому каждая точка
  отрабатывается до полной остановки. Для сборки башни это и нужно: точное
  позиционирование вместо скругления углов. Побочно — `C_DIS` в `CASE 4/5`
  фактически не даёт скругления.

## Замеченное в Python-части (не в KRL)

`COM_LENGTH` пишется как `len(массива) - 1`, а KRL читает индексы с 1. То есть
**нулевая строка массива никогда не исполняется** — она служит слотом под
текущую позицию. Сейчас это работает, потому что траектория всегда строится как
`[текущая_поза, цель]`. Но если однажды передать настоящую многоточечную
траекторию, первая точка молча потеряется. `CASE 11` и `CASE 12` этой ловушки
лишены: они работают с одиночными переменными, а не с массивом.

## dist3: команды магазина

`CASE 20` — взять кубик из слота `COM_VALUE1`, `CASE 21` — вернуть обратно.

Траектории не выдуманы: они повторяют рабочие программы стенда `kkkk/takeCube_1..6`,
которые уже отлажены. Оттуда же взяты координаты:

```
подход    X = -205        вход      X = -258     (глубина 53 мм)
ориентация A=0 B=90 C=180 — одинакова у всех слотов

слот 1  Z = 226.0      слот 4  Z = 410.5
слот 2  Z = 287.5      слот 5  Z = 472.0
слот 3  Z = 349.0      слот 6  Z = 533.5        шаг ровно 61.5 мм
```

Замер подтвердил, что шаг постоянный, а ориентация губок у всех слотов одна и та
же. Поэтому ручное заучивание поз магазина не нужно — эти координаты точнее.

Смыкание губок повторяет проверенную последовательность:
`$OUT[2]=FALSE` → 0.1 с → `$OUT[1]=TRUE` → 0.5 с. Размыкание зеркально.

Отличия от исходных программ, сделанные сознательно:

- **скорость снижена** до `$VEL.CP = 0.2` вместо 0.7 — это наладка, поднимать
  после первого успешного прогона;
- **скругление `C_DIS` убрано**: в диспетчере стоит `$ADVANCE = 0`, при котором
  опережающий просмотр выключен и скругление всё равно не работает. Каждая точка
  отрабатывается до полной остановки, что для захвата даже лучше.

Запуск с компьютера:

```bash
python tools/magazine.py --probe            # состояние, движения нет
python tools/magazine.py --take 1           # взять из нижнего слота
python tools/magazine.py --take 1 --put 1   # взять и сразу вернуть
```
