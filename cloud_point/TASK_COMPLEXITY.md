# Задача: Оценка вычислительной сложности совмещения облаков точек

## Название задачи

**Эмулятор вычислительной нагрузки для регистрации облаков точек от двух RGB-D камер в реальном времени**

---

## Формулировка задачи

### Контекст

Система использует две RGB-D камеры с параметрами:
- Разрешение: **848×480 пикселей**
- Частота: **90 FPS**
- Поток точек: 848 × 480 × 90 ≈ **36.6 млн точек/с**
- Точек на кадр: 848 × 480 = **407,040 точек**

### Даны

| Параметр | Обозначение | Описание |
|----------|-------------|----------|
| Размер облака A | N | Количество точек в первом облаке |
| Размер облака B | M | Количество точек во втором облаке |
| Радиус поиска | r | Радиус поиска соответствий (м) |
| Целевое время | t₀ | Желаемое время обработки кадра (мс) |
| Макс. частота | Fmax | Максимальная частота обновления (FPS) |
| Мощность | P | Доступная вычислительная мощность (FLOPs/с) |
| Точки интереса | k | Максимальное число keypoints |
| Тип алгоритма | A/B/C | Выбор алгоритма совмещения |
| Точность | ε | Требуемая точность совмещения |
| Эффективность | η | Коэффициент использования CPU (0-1) |

### Цель

1. Оценить **FLOPs** для выбранного алгоритма
2. Вычислить **t_calc** — время расчёта на один кадр
3. Определить **t_cap** — достижимую частоту кадров
4. Дать **рекомендации** по выбору алгоритма и параметров
5. Оценить **требуемую память**

## Математическая модель

### Алгоритмы и их сложность

#### Алгоритм A: Наивный перебор (Brute Force)

$$
\text{FLOPs}_A \approx c_1 \cdot N \cdot M
$$

где $c_1 \approx 15$ — операций на пару точек (вычисление расстояния + сравнение).

**Сложность:** $O(N \cdot M)$

#### Алгоритм B: Локальный поиск в окне (Local Search)

$$
\text{FLOPs}_B \approx c_2 \cdot N \cdot w
$$

где:
- $c_2 \approx 20$ — операций на точку в окне
- $w$ — размер окна поиска

**Размер окна:**

$$
w = \rho \cdot \frac{4}{3}\pi r^3
$$

где $\rho = N / V$ — плотность точек, $V$ — объём пространства.

**Сложность:** $O(N \cdot w)$

#### Алгоритм C: Грубая фильтрация + точный подбор (Coarse-to-Fine)

$$
\text{FLOPs}_C \approx c_3 \cdot N \log N + c_4 \cdot N \cdot w
$$

где:
- $c_3 \approx 5$ — операций для построения KD-дерева
- $c_4 \approx 25$ — операций для точного подбора

**Сложность:** $O(N \log N + N \cdot w)$

### Время расчёта

$$
t_{calc} = \frac{\text{FLOPs}}{\eta \cdot P}
$$

где:
- $\eta$ — коэффициент эффективности (учитывает накладные расходы, кэш-промахи)
- $P$ — теоретическая производительность CPU

### Достижимая частота кадров

$$
t_{cap} = \min\left(F_{max}, \frac{1000}{t_{calc}}\right) \text{ FPS}
$$

### Прогноз памяти

$$
\text{Memory} = \underbrace{(N + M) \cdot 3 \cdot 4}_{\text{точки (float32)}} + \underbrace{2N \cdot 4}_{\text{индекс}} + \underbrace{k \cdot 16}_{\text{соответствия}} \text{ байт}
$$

В мегабайтах:

$$
\text{Memory}_{MB} = \frac{(N + M) \cdot 12 + 8N + 16k}{1024^2}
$$

## Эмулятор расчёта

### Описание

Эмулятор **НЕ обрабатывает реальные кадры**. Он:

1. Генерирует **синтетические облака точек** (случайные 3D координаты)
2. Вычисляет **теоретические FLOPs** по формулам
3. Рассчитывает **t_calc** и **t_cap**
4. Опционально измеряет **реальное время** на уменьшенных данных

### Псевдокод

```python
def emulate_frame(params):
    # 1. Генерация синтетических облаков (НЕ реальные данные!)
    cloud_A = random_points(params.N, bounds=(1,1,1))
    cloud_B = random_points(params.M, bounds=(1,1,1))
    
    # 2. Вычисление теоретической сложности
    if params.algorithm == 'A':
        flops = c1 * N * M
    elif params.algorithm == 'B':
        w = calculate_window(N, r)
        flops = c2 * N * w
    elif params.algorithm == 'C':
        w = calculate_window(N, r)
        flops = c3 * N * log(N) + c4 * N * w
    
    # 3. Расчёт времени
    t_calc = flops / (eta * P)
    t_cap = min(Fmax, 1000 / t_calc)
    
    # 4. Оценка памяти
    memory = estimate_memory(N, M, k, algorithm)
    
    # 5. Рекомендации
    if t_calc > t0:
        recommendations = suggest_optimizations(params, t_calc)
    
    return {flops, t_calc, t_cap, memory, recommendations}
```

### Пакетный режим

```python
def batch_emulation(params, n_frames=10):
```

## Ограничения и проверки

### Критические ограничения

1. **⚠️ РЕАЛЬНЫЕ КАДРЫ НЕ ИСПОЛЬЗУЮТСЯ**
   - Все облака точек — синтетические
   - Система моделирует вычислительную нагрузку

2. **Проверка реального времени:**
   ```python
   if t_cap >= t0:
       status = "Задача выполнима в реальном времени"
   else:
       status = "Требуется оптимизация"
   ```

3. **Рекомендации при превышении времени:**
   - Сменить алгоритм (A → B или C)
   - Уменьшить радиус поиска r
   - Применить децимацию (уменьшить N, M)
   - Уменьшить число точек интереса k
   - Увеличить вычислительную мощность P

### Валидация параметров

```python
assert N > 0 and M > 0, "Размеры облаков должны быть положительными"
assert 0 < r < 1, "Радиус должен быть в диапазоне (0, 1) м"
assert 0 < eta <= 1, "Эффективность должна быть в (0, 1]"
assert algorithm_type in ['A', 'B', 'C'], "Неизвестный алгоритм"
```
